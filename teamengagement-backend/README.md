# The Report-Out — Google Sheets setup

The employee-facing site remains at:
https://phenom1881.github.io/slidedeckupdate/teamengagement.html

Host controls are at:
https://phenom1881.github.io/slidedeckupdate/teamengagement.html?host

This page is hosted on GitHub Pages. A private Google Sheet stores the questions,
responses, and request receipts. Employees need **no GitHub or Google accounts**.
Anyone who gets the team link can participate: it is unlisted, **not access-controlled**
beyond the unguessable link key. The Google Sheet itself stays private.

## One-time setup (Google account owner)

1. Create a **new blank Google Sheet**, e.g. `Team Engagement Responses`.
   Keep it private. Do **not** share the Sheet with the whole team.
2. In that Sheet, go to **Extensions → Apps Script**.
3. In the editor, replace the contents of `Code.gs` with the full contents of
   [Code.gs](Code.gs) from this directory in GitHub, and **Save**.
4. In the function dropdown choose `setupReportOut`, click **Run**, authorize
   the spreadsheet permissions, and check the **Execution log**. Copy the
   displayed **HOST KEY** to your private password manager. Don't put it in GitHub,
   in a screenshot, or in the employee link.
5. Click **Deploy → New deployment**; select **Web app**. Set:
   - **Execute as:** Me (the Sheet owner)
   - **Who has access:** Anyone
   Click **Deploy** and copy the final web-app URL. It should look like
   `https://script.google.com/macros/s/DEPLOYMENT_ID/exec`.
   If Google Workspace administrators disallow anonymous web apps, you will need
   an approved alternative account/service.
6. In [../teamengagement.html](../teamengagement.html), find:
   `window.REPORT_OUT_API = "";`
   Replace the empty string with your copied `/exec` URL. Commit that
   one-line change to the existing `main` branch.
7. Open the **Host Controls** link above, enter your HOST KEY, and create your
   first question. Click **Copy team link** and share that generated link.
   **Do not share the base page URL alone**—the generated link contains the
   random team key after a `#` and makes the cloud work for employees.
8. Test using a private/incognito window. Submit an answer, check that it appears,
   then open a second browser/device to verify the cloud updates.

## Everyday use

- Host controls: create a question, automatically close the previous round,
  close a current question, see historical response counts, and download a CSV
  for a question or the full history.
- Team link: use the **same generated link** for every new question. No login.
  One response per browser/device per question (best effort; not identity proof).
- The host's display link offers a full-screen-friendly answer cloud. It refreshes
  every ~3 seconds.
- Exported CSVs include a question identifier, question text, round dates, answer
  timestamp and individual answer.
- Original answers and question history remain in the private Google Sheet.

## Important limitations

- Google Apps Script deployment is an **anonymous public web app** to allow
  account-free answers. It does not prove somebody is on your team; anyone who
  gets the team link can respond. Do not ask for sensitive personal information.
- The host key is a separate strong secret, generated by `setupReportOut` and
  verified on the backend. Never share it with employees.
- Replies are not literally real-time push events: the webpage polls every 3
  seconds. Script/Sheet quotas can affect very large events.
- `google.script.run` isn't used; the page uses a JSONP GET for results and
  an iframe POST + receipt check for cross-origin writes. Because callbacks
  aren't an access-control security boundary, **do not use this system for
  confidential information**.
- Changing `Code.gs` later requires **Deploy → Manage deployments → Edit →
  New version → Deploy** to publish the new backend code.
- A Google Apps Script URL alone won't run the system until you also set the
  URL in the GitHub HTML file.
